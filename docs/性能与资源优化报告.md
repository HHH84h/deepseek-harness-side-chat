# v1.0.2 性能与资源优化报告

## 采用的工程方法与来源

| 来源 | 工程建议 | 本项目落实 |
|---|---|---|
| [Electron 性能指南](https://www.electronjs.org/docs/latest/tutorial/performance) | 先测量、定位，再优化；减少不必要工作和界面阻塞 | 同一机器与测试场景比较基线；保留既有功能，不凭体感宣称更快 |

| [Nolan Lawson：Web 内存泄漏](https://nolanlawson.com/2020/02/19/fixing-memory-leaks-in-web-applications/) | 重复操作、暖机、回收后比较；成对释放监听器、观察器、计时器和全局缓存 | 客户端反复替换/切换测试，以及真实浏览器 20 次开关；覆盖卸载、取消和异常 |

## 确认并修复的问题

- 导航容器被重建后，旧节点仍留在插件集合中：检测断开并移除强引用，卸载恢复样式。
- 每个访问过的会话都留下统计源：最后一个订阅者退出即删除缓存；退订幂等，活动订阅期间保持快照稳定。
- 所有权握手取消与绑定取值异常可能滞留 retain：再次检查取消；统一 finally 释放引用与中断监听。
- 关闭后延迟 RPC 与重复打开轮询可能继续：跟踪并取消计时器，同一主聊合并绑定查询，卸载后不再更新界面。
- 宿主请求 ID 集合随发送数累积：仅覆盖 inbox 未落盘窗口；日志接纳后移出集合，持久日志继续负责去重。
- 卸载时缓存和异步创建可能存活：清理实例状态，释放自己拥有的句柄，迟到的创建结果立即释放；磁盘恢复记录保留。
- ZIP 下载曾保留全部分块，再拼接一份完整副本：改为有背压的文件管线和流式散列。实测取消时发现直接桥接 Web 流可能等待未完成读取，已改用 Node 的 Web 流适配器并添加阻塞取消测试。
- 自动化只发退出信号、未等待退出：增加确认、有限等待和本次进程组清理。启动日志只保留有限尾部，测试报告和控制台错误设置数量上限。

## 修改前后数据

环境：本机 macOS、Node 24、Edge 155、Harness CLI 0.2.1-rc.2；临时测试 home、虚构问题、离线 provider。下表不是其他机器的保证值。

| 测量 | v1.0.1 | v1.0.2 | 解释 |
|---|---:|---:|---|
| 替换 100 次导航分组后，插件保留的已断开容器引用 | 100 | 0 | 定向夹具复现与断言，不是整应用堆大小 |
| 访问并退订 100 个主聊后，插件保留的统计源 | 100 | 0 | 订阅期间仍稳定，结束后释放 |
| 16 MiB 模拟下载，数组缓冲区峰值增量 | 32.1 MiB | 7.9 MiB | 单次独立 Node 进程测量，约减少 75%；仅下载阶段 |
| 同一下载，RSS 峰值增量 | 51.5 MiB | 17.6 MiB | 含运行时/分配器影响，不能推广为整应用降幅 |
| 20 次侧聊开关，中位耗时 | 573 ms | 573 ms | 含固定等待；没有测出明显提速或退化 |
| 20 次开关，强制回收后 JS 堆增量 | 约 3.55 MiB | 约 3.57 MiB | 本场景没有可证实的整体堆改善 |
| 20 次开关，页面总节点/监听器增量 | 1,200 / 60 | 1,200 / 60 | 新版同时测得连接节点增量正好 1,200 |

新版的节点增长全部连接在页面中，与主聊保留命令历史的行为一致；这不支持把该增长直接判为 detached DOM 泄漏。尚未做每个监听器的堆持有链归因、长时间真实模型压测或原生 Electron 全进程测量，因此不声称“所有泄漏已解决”。宿主 RSS 中出现 GC 波动，也没有被当成优化收益。

流式下载后仍须做 ZIP 安全结构检查；该阶段一次读取不超过 16 MiB 的 ZIP，不是全流程恒定内存。16 MiB 是支持上限，当前安装附件远小于该值。

## 自动结束与进程边界

| 场景 | 行为 |
|---|---|
| 安装/检查/回退/卸载成功 | 脚本立即退出，不等回车 |
| 操作失败 | 按回车或最多等 20 秒，保留原退出码 |
| 显式 `SIDE_KEEP_OPEN=1` | 由使用者选择等待回车 |
| 等待更新确认 | 两分钟无输入、输入结束或取消均停止，不默认同意 |
| 更新下载失败/超限/取消 | 释放流、关闭文件，清除本次半成品，保留原有文件 |
| 系统版本/运行状态检查 | 设置超时及输出上限；结果未知时停止修改 |
| 隔离测试服务和浏览器 | 结束时等待退出，必要时升级信号，清理本次拥有的进程组及临时目录 |

已用伪终端验证成功退出无需 Enter/EOF、失败有界等待路径及显式保留；失败测试用受控 read 夹具加速等待，没有声称真实等待了 20 秒。原生 Finder/Gatekeeper 与 Terminal 可视关闭没有重新验收，也没有绕过终端 UI 的访问限制。安装事务本身不新增粗暴强杀超时，以免在写配置中途破坏恢复。

没有新增系统定时任务、LaunchAgent、登录项、后台更新守护进程或自动更新用户应用的操作。
